Git & GitHub Handbook

Simple guide for developers and non-programmers

1. The Basics: What are Git and GitHub?

Think of your project like writing a manuscript:

  • Git: An automatic "save history" manager on your local computer. It records snapshots of your files every time you commit.
  • GitHub: A cloud host (like Google Drive for code) that backs up your Git repositories so you can share and collaborate online.
  • Repository (Repo): Your project folder tracked by Git.
  • Branch: A safe parallel line of work (e.g., phase4) where you can build features without breaking the working main version.

2. Standard Commands: Push & Pull

The core three-step cycle to push work to GitHub:

# 1. Stage all changed files
git add .

# 2. Save snapshot with a descriptive note
git commit -m "Update homepage layout"

# 3. Upload to GitHub
git push

Fetching Remote Updates

If someone else updated GitHub or you made edits on another machine, pull down the latest version:

git pull origin main

3. Setting Up a Downloaded ZIP on a New Branch

Downloaded a ZIP instead of cloning? Relink it to your online repo and push your changes to a new branch like phase4:

# Initialize tracking in this folder
git init

# Connect to your remote repository
git remote add origin https://github.com/username/repository.git

# Create & switch to new branch
git checkout -b phase4

# Commit and push up your files
git add .
git commit -m "Add local progress to phase4"
git push -u origin phase4

4. Undoing Mistakes & Checking Status

Git acts as your safety net. Here is how to inspect and undo local changes:

  • git status — See which files have been edited, staged, or remain untracked.
  • git diff — Preview line-by-line changes before staging them.
  • git restore filename.js — Discard local edits and reset a file back to its last committed state.
  • git reset HEAD~1 --soft — Undo your last commit, but keep all your file changes safe on your computer.

5. Merging & Pull Requests

Once your work on phase4 is complete, you will want to combine it back into the main codebase.

Option A: The GitHub Way (Recommended)

  1. Push your branch to GitHub (git push -u origin phase4).
  2. Open GitHub in your browser—you will see a banner asking to "Compare & pull request".
  3. Click it, add a summary of your changes, and hit Create Pull Request.
  4. Review your changes online and click Merge Pull Request.

Option B: Command Line Merge

# Switch back to main
git checkout main

# Download latest main updates
git pull origin main

# Combine phase4 into main
git merge phase4

# Push updated main to GitHub
git push origin main

6. Understanding & Resolving Merge Conflicts

A merge conflict happens when two people (or branches) change the exact same line of a file in different ways, and Git doesn't know which one to keep.

What Git does: Git pauses the merge and highlights the conflict inside your file like this: 
<<<<<<< HEAD (Your Current Code)
const title = "Welcome back!";
=======
const title = "Hello World!";
>>>>>>> phase4 (Incoming Code)

How to fix a conflict:

  1. Open the file in your code editor.
  2. Delete the unwanted version along with Git's marker lines (<<<, ===, >>>).
  3. Save the file.
  4. Run: 
    git add .
git commit -m "Resolved merge conflict"

7. Stashing: Temporarily Hiding Unfinished Work

Need to quickly switch branches to fix a bug, but your current edits aren't ready to be committed?

# Save unfinished edits to a temporary shelf
git stash

# Switch branches and do whatever work is needed...
git checkout main

# Switch back and restore your stashed edits
git checkout phase4
git stash pop

8. Troubleshooting Accordion (Common Errors)

Error: "fatal: detected dubious ownership in repository"

Cause: You are accessing a repository owned by a different system user (e.g., executing as root in Linux/WSL).

Fix: Instruct Git to trust the project path globally:

git config --global --add safe.directory /opt/trackmp
Error: "Password authentication is not supported"

Cause: GitHub disabled standard account password auth for Git operations.

Fix: Generate a Personal Access Token (PAT):

  1. Go to GitHub: Settings > Developer settings > Personal access tokens > Tokens (classic).
  2. Generate a token checking the repo permissions box.
  3. Paste this token when Git prompts for your password in terminal.
How to ignore specific directories (e.g., backend/uploads/)

Append the relative path from your repo root to .gitignore:

echo "backend/uploads/" >> .gitignore

If the folder was already tracked previously, untrack it without deleting local files:

git rm -r --cached backend/uploads/
git commit -m "Stop tracking uploads directory"
