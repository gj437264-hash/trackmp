LibreCrawl Local Setup & SSL Troubleshooting

Complete technical reference guide for resolving Python PEP 668, requests SSL errors, and Playwright/Chromium certificate failures on WSL/Linux.

Issue 1: Externally Managed Environment (PEP 668)

Setup / Environment

Error Logs

error: externally-managed-environment × This environment is externally managed ╰─> To install Python packages system-wide, try apt install python3-xyz... Failed to install dependencies!

Cause

Modern Debian/Ubuntu installations prevent global pip install commands on system Python to protect OS package dependencies.

Fix 1: Virtual Environment (Recommended)

# 1. Install Python venv package
sudo apt update && sudo apt install -y python3-venv python3-full

# 2. Create virtual environment inside project directory
python3 -m venv venv

# 3. Activate the virtual environment
source venv/bin/activate

# 4. Re-run start script
bash start-librecrawl.sh

Fix 2: Bypass PEP 668 Globally

pip config set global.break-system-packages true
bash start-librecrawl.sh

Issue 2: Python HTTP Requests Certificate Verification Failure

SSL / Network

Error Logs

HTTPSConnectionPool(host='your-domain.com', port=443): Max retries exceeded with url: /robots.txt (Caused by SSLError(SSLCertVerificationError(1, '[SSL: CERTIFICATE_VERIFY_FAILED] certificate verify failed: unable to get local issuer certificate (_ssl.c:1007)')))

Cause

Python running inside WSL relies on the Linux CA trust store or certifi bundle, which does not automatically include mkcert root CAs installed on Windows host system.

Fix: Import Windows mkcert CA into WSL

  1. Get the mkcert Root CA directory in Windows PowerShell: 
    mkcert -CAROOT
  2. Copy the certificate into WSL trust store and update system CA database: 
    # Create directory
sudo mkdir -p /usr/local/share/ca-certificates/

# Copy root certificate from Windows (replace YourUsername)
sudo cp /mnt/c/Users/YourUsername/AppData/Local/mkcert/rootCA.pem /usr/local/share/ca-certificates/mkcert-rootCA.crt

# Update Linux trusted certificates
sudo update-ca-certificates
  3. Set Python SSL environment variables (Add to ~/.bashrc for persistence): 
    export REQUESTS_CA_BUNDLE=/etc/ssl/certs/ca-certificates.crt
export SSL_CERT_FILE=/etc/ssl/certs/ca-certificates.crt

Issue 3: Playwright / Chromium Headless Navigation Certificate Error

Headless Browser

Error Logs

Status Code: 0 (SSL/TLS Error) Error: Navigation error: Page.goto: net::ERR_CERT_AUTHORITY_INVALID at https://your-domain.com/ Call log: - navigating to "https://your-domain.com/", waiting until "domcontentloaded"

Cause

LibreCrawl uses Playwright/Chromium to crawl pages and gather DOM elements. Chromium does not use Python's CA settings or Linux system cert store by default; it uses Network Security Services (NSS) or strict internal certificate checks.

Fix 1: Trust CA in Chromium's NSS Database (Linux)

# 1. Install NSS tools
sudo apt update && sudo apt install -y libnss3-tools

# 2. Create NSS database folder if missing
mkdir -p ~/.pki/nssdb
certutil -d sql:$HOME/.pki/nssdb -N --empty-password

# 3. Add mkcert CA to Chromium trust store
certutil -d sql:$HOME/.pki/nssdb -A -t "C,," -n "mkcert root ca" -i /usr/local/share/ca-certificates/mkcert-rootCA.crt

Fix 2: Launch Playwright with SSL Flag (Code Level)

If modifying source code, add browser context options in the crawler startup:

# Playwright Python context settings
context = await browser.new_context(
    ignore_https_errors=True
)

# Playwright Launch Arguments
browser = await playwright.chromium.launch(
    args=['--ignore-certificate-errors', '--allow-insecure-localhost']
)

Quick Workflow Reference

# 1. Start virtualenv
source venv/bin/activate

# 2. Export system CA paths
export REQUESTS_CA_BUNDLE=/etc/ssl/certs/ca-certificates.crt
export SSL_CERT_FILE=/etc/ssl/certs/ca-certificates.crt

# 3. Run application
bash start-librecrawl.sh
